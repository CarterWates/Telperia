Measurement philosophy

AI performance should include what the model costs to run.

01 Capability

What can the model complete under a controlled benchmark suite?

02 Trust

How reliable are its factual answers, what remains unscored, and what evidence backs the run?

03 Efficiency

What local GPU energy was consumed, and how much capability per watt-hour did it produce?

Result provenance

Selected result

Each accepted result keeps public comparison fields separate from raw private JSON. The detail view shows what can be inspected without exposing prompts or responses.

Methodology

Versioned methods, inspectable outputs.

Telperia scores are useful only when the measurement process is visible. Current MVP packages preserve methodology version, benchmark suite, hardware, telemetry source, energy scope, local inference energy, and verification level.

TCI v0.1

Capability score across reasoning, coding, mathematics, factual knowledge, and instruction adherence.

Factual Reliability

Correct, incorrect, abstained, and attempted-accuracy rates for factual tasks.

Local IPW v0.1

Local IPW measures capability per watt-hour of local GPU energy. Hosted and data-center IPW remain separate future work.

TRI: Not yet scored

Planned reliability index for consistency, operational stability, completion behavior, and repeatability.

Transparency Evidence

Shown as inspectable metadata for model revision, runtime, hardware, raw package availability, and verification.

Hardware-aware evaluation

The machine is part of the result.

Telperia treats hardware, monitor backend, operating system, energy scope, and local power telemetry as first-class metadata. Current measured seed results use a Windows RTX 5070 with NVML.

Windows NVIDIA Measured Local IPW with NVML
Linux NVIDIA Supported when NVML is available
Mac local development Capability runs; Local IPW deferred
Hosted/datacenter Future methodology; not mixed with Local IPW

Current status

Phase 6 is private-by-default ingestion.

  1. Local runner, telemetry, schemas, and result validation are implemented.
  2. Local API skeleton exists; live Supabase writes are not connected yet.
  3. The public Observatory is a static shell using seed public-safe data from local result packages.
  4. Local-first contribution keeps uploads private by default, with explicit public review submission for approved public summaries.
  5. Prompt and response content is not collected for public results.
  6. Community auth and reviewer workflows come after ingestion.
